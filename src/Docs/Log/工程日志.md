## 2. 系统方案 (最终确定)

```
Orin AGX (感知)                    x86 (控制)
┌────────────────────┐   DDS   ┌───────────────────┐
│ YOLO ×1 (3类)      │──────→ │ 任务状态机          │
│  usb_a_port → PnP  │ Topic  │ 抓取 (位置+OBB角度)  │
│  usb_a_plug → 深度 │        │ 插入 (垂直下插+力确认)│
│  type_c_end (区分)  │        │ 六维力 100Hz        │
│ 相机驱动(RGBD)     │        │ 关节伺服 400Hz      │
└────────────────────┘        └───────────────────┘
```

**为什么比最初方案大幅简化：**

| 简化点 | 原因 |
|--------|------|
| 不需要螺旋搜孔 | USB-A 容差 3mm，垂直下插+重力辅助 |
| 不需要导纳控制 | 口朝上+方向一致，纯位置控制即可 |
| 不需要 ACT / RL | 场景完全可显式建模 |
| 不需要姿态估计网络 | 插头平放→OBB角度就够了 |
| 不需要多次扫描插排 | 插排固定，扫一次存盘 |

**模型策略：一个 YOLO，一个 PnP**

```
YOLO ×1 (3类, Orin TensorRT):
  class 0: usb_a_port   → bbox 送 PnP → 6D位姿 → 存盘
  class 1: usb_a_plug   → bbox + OBB角度 + 深度图 → 3D位置+偏航角
  class 2: type_c_end   → 仅区分，不操作

PnP (非学习, 几何算法):
  仅用于插排母口: 矩形角点(已知USB-A口物理尺寸) → 精确6D位姿
  插头不做PnP — 俯视是侧面，看不到矩形口
```

**传感器分工：**

| 传感器 | 用途 |
|--------|------|
| 头部 RGBD (Orin) | 检测插头/母口、深度图拿位置 |
| 六维力 (x86, 100Hz) | 插入阻力监控、抓取确认，不做搜孔 |
| 关节编码器 (x86, 400Hz) | 位置控制、正运动学算末端位姿 |

## 13. 遥操数采系统架构分析 (2026-07-17)

### 整体架构确认

三机协同: 工控机(同构臂CAN采集) → 笔记本(数据融合+DDS发布) → 机器人(执行+录制)

```
工控机 192.168.41.100 (无ROS2)
  同构臂 TS1P ──CAN──→ fast_sync ──ZMQ──→ :5001 手臂关节角
                                          :5002 手柄状态

笔记本 192.168.41.5 (有ROS2, eai_env)
  Manus手套 ──USB──→ SharpaManusClient ──ZMQ:6667──→ retargeting ──ZMQ:6668──→ 手部关节
  工控机:5001 ──ZMQ SUB──────────────────────────────────────────────→ 手臂关节
                        ↓ 融合 (integrate_module)
                 ROS2/DDS ──→ 机器人 192.168.41.1

机器人 192.168.41.1
  DDS → freq_change(力位混合控制) → bodyctrl(ServoTeleCore) → EtherCAT/CAN → 电机
  xrocs --mode data_collect → HDF5 录制 (关节60Hz+相机30Hz+力100Hz)
```

### 关键发现

1. **工控机没有 ROS2**, 只通过 ZMQ 发送同构臂数据给笔记本, 不直接控制机器人
2. **笔记本是数据中枢**, 手套 USB 直连 + ZMQ 拉同构臂 → 融合后 ROS2/DDS 发给机器人
3. **控制机器人的是 bodyctrl**, 链路: xtele(DDS) → freq_change(桥接) → bodyctrl(ServoTeleCore) → 电机
4. **数采由 xrocs 完成**, `xhumanoid-xrocs --mode data_collect` 录制全身关节+相机+力传感器为 HDF5
5. **fast_sync 是工控机端主循环**, 读 CAN 同构臂 + 手柄 WebUI → ZMQ 发布, 由 PostTeleAgent 做数据融合
6. **xtele SDK (v0.0.8)** 含完整硬件驱动(达妙电机/CAN/手套/动捕/手柄/IMU/踏板)和 fast_sync 模块(按钮控制/手势控制/超时管理)

## 18. XARM 分析 & body_control 自带的规划能力 (2026-07-20)

### XARM 是什么

XARM 是一个预编译的 colcon workspace（V1.2.27），从机器人 x86 上整体打包。含 71 个包，分四类：

| 类别 | 数量 | 举例 |
|------|:--:|------|
| 天轶2 专用 | 6 | `tianyi2_description`, `tianyi2_moveit_config`, `tianyi2_bringup`, `tianyi_controller`, `tianyi_hardware`, `tianyi_sim` |
| 其他机器人 | 9 | `tiangong2_description`, `tiangong2dex_moveit_config`, `dual_arm_v2_*`, `xarm_manager` |
| 自定义控制器 | ~10 | `single_arm_qp/qp2/qpik/rmp2`, `endpose_*`, `wholebody_qpik`, `head_ik`, `jointspace_ruckig_*`, `admittance` |
| 标准 ROS2 库 | ~46 | `controller_manager`, `ros2_control`, `moveit_*`, `rmpflow`, `qpik` 等 |

**XARM 比我们自生成的 moveit_ws 多出的有用内容：**

| 文件 | 用途 |
|------|------|
| `ompl_planning.yaml` | 路径规划参数（我们缺的） |
| `moveit_controllers.yaml` | MoveIt→控制器关节映射（真机连动时用） |
| `initial_positions.yaml` | home 位姿定义 |
| SRDF 多了 `trunk`、`body` 规划组 | 腰部/全身也能规划 |
| `tianyi2_description` 多了 10+ URDF 变体 | dual/wholebody/upper_body/QP 等场景 |

**问题**：XARM 文件名有 `.0` 缺失 bug（`tianyi2.0_complete.xacro` 缺位），需 symlink 修复。且 `setup.bash` 硬编码 `/home/ubuntu/` 路径，不能直接 source，只能用 `local_setup.bash`。

### body_control 自带规划能力

读取机器人 `ROS/ros2ws/install/bodyctrl_msgs/` 发现，body_control 内置了 3 个末端规划 Service：

| Service | 输入 | 功能 |
|---------|------|------|
| `PlanEefLine` | `arm_name` + `eef_pose`(Pose) + 速度/加速度比例 | **绝对笛卡尔空间移动** |
| `PlanEefRelLine` | `arm_name` + `dx,dy,dz`(米) + 速度/加速度比例 | **相对移动**（"往下移3cm"） |
| `PlanJointTraj` | `arm_name` + 目标关节角 + 速度/加速度/jerk | **关节空间移动** |

### 两种控制方案对比

```
方案 A: body_control 自带 Service（简单快速）
  相机 → YOLO/PnP → USB口位姿
  → PlanEefLine(arm="left", pose=above_port)
  → PlanEefRelLine(arm="left", dz=-0.03) 下插
  → 力传感器确认
  → 松手

方案 B: MoveIt2 + body_control（有避碰）
  相机 → YOLO/PnP → USB口位姿
  → /dual_arm_waypoints Service → move_group → OMPL避碰规划 → /arm/cmd_pos
  → 力传感器确认
  → 松手
```

| | body_control 自带 | MoveIt2 |
|--|:--:|:--:|
| 笛卡尔移动 | ✅ PlanEefLine | ✅ move_group |
| 相对移动 | ✅ PlanEefRelLine | ❌ 需自己算 |
| 碰撞检测 | ❌ 无 | ✅ OMPL |
| 多路点 | ❌ 单点 | ✅ 轨迹 |
| 外部依赖 | 零 | move_group + dual_arm_control |
| 适用场景 | 简单抓放 | 复杂轨迹/避碰 |

**结论**：比赛方案用 body_control 自带 Service 为主，MoveIt2 作为碰撞规避补充。两者可以混用——先用 PlanEefLine 快速到位，需要避碰时才调 MoveIt2。

### 机器人控制架构 — 双系统并存（重大发现）

机器人上有**两套并行的控制体系**，都可以从外部调用：


## 21. 真机控制调试 & 根因分析 (2026-07-20)

### 背景

XARM + body_control 双系统上线后，所有控制指令（`/arm/cmd_pos` topic、`/jointspace_commands_L` XARM 指令）均无法驱动机器人手臂，头部可以正常控制。

### 系统架构全景

机器人上跑着两套控制链路，共用同一个下游 topic `/arm/cmd_pos`：

```
链路 A（遥控）:
  SBUS → usb_sbus → teleop_dispatcher → /arm/cmd_pos

链路 B（算法 / XARM）:
  controller_manager (ros2_control)
    ├── jointspace_arm_L_controller (inactive→active)
    ├── joint_state_broadcaster (active)
    └── EAIHardware (TianyiHardware, active)
          读 /arm/status ← bodyctrl 电机状态
          写 /arm/cmd_pos → bodyctrl 位置指令

                    ↓
          bodyctrl_component
                    ↓
           U2C CAN 总线 → 14个臂关节电机
```

`/arm/cmd_pos` 是唯一瓶颈 — 所有控制源都往这里写，bodyctrl 只订阅这一个 topic 来驱动机器人。

### 根因：250Hz 指令覆盖

`/arm/cmd_pos` 上同时有多个发布者：

| 发布者 | 频率 | 发布内容 |
|--------|:--:|------|
| `EAIHardware` (ros2_control) | **250Hz** | 从 `/arm/status` 读取的当前位置（hold current position） |
| `teleop_dispatcher` (x2) | 低频 | 遥控器位置指令 |
| 手动 `ros2 topic pub --once` | 单次 | **被覆盖** |

EAIHardware 每 **4ms** 发布一次"保持当前位置"指令。任何从外部 `ros2 topic pub --once` 发出的指令存活不到 4ms 就被 EAIHardware 覆盖回原位置。

**验证**：kill ros2_control_node 后，`ros2 topic pub /arm/cmd_pos` 立即能驱动电机。

### FakeSystem 名字误导

`ros2 control list_hardware_components` 输出 `FakeSystem`，但插件是 `tianyi_hardware/TianyiHardware`（真硬件），不是 `mock_components/GenericSystem`（仿真）。 "FakeSystem" 只是 xacro 里写死的 ros2_control 实例名，由 `hardware:=real` 参数控制实际加载的插件。名字叫 Fake，功能是真硬件。

### 正确使用方式

当不需要 ros2_control 接管关节时，应切到 `empty_controller`：

```bash
ros2 control switch_controller \
  --deactivate jointspace_arm_L_controller \
  --activate empty_L_controller empty_R_controller
```

`empty_controller` 声明了 joint command interface 但不往 `/arm/cmd_pos` 写任何东西，把控制权完全还给外部指令。

### 手动跳过自检的完整步骤

1. SSH x86: `sudo systemctl stop proc_manager`
2. 编辑 `/home/ubuntu/data/param/u2c_sn.yaml` 设 `enable_hands: false`
3. `ros2 launch body_control body.launch.py`
4. 笔记本 source XARM: `source ~/WireConnect_ws/ROS/robot_pkgs/XARM/install/setup.bash`
5. XARM 必须带 `hardware:=real` 启动

### 可用控制链路总结

| 方式 | 命令 | 适用场景 |
|------|------|------|
| body_control 直发 | `ros2 topic pub /arm/cmd_pos ...` | 头部控制、单关节测试 ✅ |
| body_control 直发 | `ros2 topic pub /arm/cmd_pos ...` (需先 kill ros2_control 或切 empty_controller) | 手臂控制 ✅ |

| XARM MoveIt Service | `ros2 service call /dual_arm_waypoints ...` | 多路点笛卡尔规划 |

### 关键 Service 速查

| Service | 消息类型 | 用途 |
